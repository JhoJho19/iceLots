# Plan.md — План разработки социального слота на Unity

**Основа:** `TZ.md`, версия 1.0.  
**Подход:** итерации с проверяемым результатом после каждого этапа, по аналогии с предоставленным референсным `PLAN.md`.  
**Приоритет:** корректность математики, сохранений и жизненного цикла Spin → затем UI/анимации → полировка.

## 1. Цель

Сделать на Unity 6 локальную социальную слот-игру с полем 5 × 3, восемью символами (в том числе Scatter), 20 линиями, Free Spins, балансом, Daily Bonus, персональным Jackpot of the Week. Игра запускается из одной сцены и имеет два экрана:

- Главное меню: `Play`, `Settings`, `Daily bonus`.
- Слот: барабаны, ставки, баланс, Spin, Back и всегда видимый JackpotHUD.

Главное архитектурное условие — Domain на чистом C#, Application для транзакций и состояния, Presentation для UI/анимаций, Infrastructure для конфигурации и сохранений, `SlotBootstrapper` как composition root. Без сетевого сервера; `ScriptableObject` сейчас, возможный `Remote Config` позднее.

**Принятая политика прерывания:** стоимость Spin сохраняется **до** анимации, вознаграждение — **после** её успешного завершения. Выход в меню во время Spin запрещён. При прекращении процесса до завершения Spin ставка (или 1 Free Spin) теряется, выигрыш не выдаётся. Это решение обязательно фиксировать в коде и тестах.

## 2. Инструменты и рабочие правила

- Unity 6, C#; Unity Test Framework (`EditMode`, `PlayMode`).
- UniTask при необходимости; tween-библиотека — только Presentation.
- ScriptableObject для локальных конфигов; Unity `Application.persistentDataPath` для сохранений через репозиторий.
- Git с небольшими, осмысленными коммитами. AI-инструменты допустимы; результаты проверять тестами.
- Domain и Application компилируются в отдельных `asmdef` без ссылок на Unity.
- Из референсного «Морского боя» перенимаем поэтапную структуру, инварианты и тестирование. **Не переносим** сетевой протокол, сервер, reconnect и эмуляцию плохой сети: для локального слота они не нужны.

## 3. Зафиксированные архитектурные решения

1. `SlotBootstrapper` собирает зависимости при запуске одной сцены.
2. Конфиг `SlotGameConfigSO` превращается в валидированный чистый C# `SlotRuntimeConfig` посредством `ISlotConfigProvider`.
3. `SlotVisualConfigSO` содержит Sprite/Prefab/визуальные параметры, не попадает в Domain.
4. `OutcomeGenerator` выбирает случайные остановки; `WinEvaluator` и `ScatterEvaluator` рассчитывают награды; `SlotEngine` не меняет баланс.
5. `SpinService` является единственной точкой выполнения вращений и соблюдает двуфазное сохранение debit/settlement.
6. `GameSession` — единственный источник статуса `Idle/Preparing/Spinning/Settling/Error`; навигация контролируется use case, а не только `Button.interactable`.
7. `BalanceService`, `DailyBonusService`, `WeeklyJackpotService` не знают о UI.
8. `ISaveRepository` сохраняет цельный versioned snapshot с `PendingSpin` и backup; после перезапуска незавершённый Spin аннулируется **без возврата ставки**.
9. `IClock` используется для Daily Bonus и недельного джекпота; `IRandomSource` допускает явный тестовый seed.
10. Все анимации показывают уже рассчитанный результат, но **не подтверждают выдачу выигрыша, пока settlement не сохранён**.

## 4. План реализации

### 4.1. Подготовка Unity-проекта, структуры и одной сцены

1. Проверить Unity 6 и подключить Test Framework / UniTask (если нужен).
2. Создать `Assets/_Project` и отдельные папки `Domain`, `Application`, `Infrastructure`, `Presentation`, `Bootstrap`, `Configs`, `Tests`.
3. Завести соответствующие `asmdef`; запретить зависимость Domain/Application от Unity.
4. Создать **одну** `Game.unity` с `SlotBootstrapper`, `Canvas`, `EventSystem`, `MainMenuScreen`, `SlotScreen`, `SettingsPopup`, `DailyBonusPopup`.
5. Установить стартовое состояние UI: показывается только Main Menu; слот неактивен.
6. Добавить базовый `.gitignore`, README-заготовку и валидный пустой startup.

**Критерий завершения:** сцена запускается с главным меню и `Play` переключает экран без загрузки второй сцены; asmdef компилируются.

### 4.2. DTO и конфигурация (ScriptableObject → Runtime)

1. Создать чистые структуры `SlotRuntimeConfig`, `SymbolId`, `ReelStrip`, `Payline`, `Paytable`, `DailyBonusRules`, `JackpotRulesConfig`.
2. Создать `SlotGameConfigSO`, `SlotVisualConfigSO`, `ISlotConfigProvider`, `LocalSlotConfigProvider`.
3. Заполнить стартовый конфиг: 5 барабанов по 30 позиций, частоты `6/5/5/4/4/3/2/1`; 20 paylines; paytable из TZ; ставки `200/400/600/800/1000`; бонусные правила.
4. Явно задать **пять реальных лент по 30 символов с разными порядками**, а не только веса; при необходимости воспользоваться editor-утилитой для первоначального создания и затем зафиксировать результат в asset.
5. Реализовать `ConfigValidator`: линии/ленты/суммы, вероятности, суммы бонусов, ограничения long и наличие нужных asset ID.
6. Обеспечить неизменность снимка конфигурации на протяжении конкретного Spin и при активной цепочке Free Spins.

**Критерий завершения:** изменение paytable, состава лент, ставки или джекпота в SO приводит к изменению соответствующей runtime-модели без правки игровой логики; невалидные данные диагностируются до старта.

### 4.3. Чистый Slot Engine: генерация результата

1. Определить `IRandomSource`, production и seed-based test implementation.
2. Реализовать `OutcomeGenerator` с пятью независимыми остановками лент и циклической выборкой трёх символов на каждой.
3. Создать `SlotGrid`, `ReelStop`, `SpinOutcome` и чистые DTO результата.
4. Создать фиксированные примеры Spin с заранее известными остановками для тестов.
5. Отдельно проверить отображаемые ряды с wrap-around при `stop=29`, `stop=28`.

**Критерий завершения:** любой результат 5 × 3 воспроизводится тестом без UI/Unity; stop-позиции однозначно определяют матрицу.

### 4.4. Чистый Slot Engine: paylines, Scatter, Free Spins и математика

1. Реализовать `WinEvaluator` для 20 линий, 3/4/5 одинаковых обычных символов **слева направо**.
2. Реализовать только максимальный оплачиваемый префикс одной линии; несколько выигрышных линий суммируются.
3. Реализовать `ScatterEvaluator` и таблицу `3→8`, `4→12`, `5→20`.
4. Реализовать `JackpotRules` (проверка шанса и применимости к платному Spin), отделив этот расчёт от reels.
5. Выразить всё в целых монетах `long`; проверить отсутствие отрицательных/переполненных значений.
6. Записать аналитические ориентиры в тестовый отчёт: base RTP ~85,6059%, with Free Spins ~92,0889%, частота Scatter 3+ ~0,856%.

**Критерий завершения:** полностью корректный расчёт выигрышей по заранее заданной матрице и модульные тесты всех ключевых правил.

### 4.5. Сохранения и восстановление

1. Описать `SaveData` с `SaveVersion`, балансом, ставкой, бонусами, weekly state, last settled spin и pending spin.
2. Реализовать `ISaveRepository` и `JsonSaveRepository` через `Application.persistentDataPath`.
3. Добавить запись через временный файл, резервную копию и проверку корректности snapshot.
4. Реализовать начальный баланс `20 000`, ставку `200` и безопасное создание нового профиля.
5. Обработать отсутствующий, повреждённый, устаревший save; предусмотреть версию и понятный сценарий сброса.
6. Добавить `FakeSaveRepository`, умеющий падать на заданной попытке записи, для тестов ошибок.

**Критерий завершения:** баланс и бонусы переживают перезапуск, фальшивые/обрезанные данные не приводят к исключению в обычном UI; ошибки записи воспроизводимы в тестах.

### 4.6. Application: Spin lifecycle и защита от прерывания

1. Реализовать `GameSession` и переходы `Idle → Preparing → Spinning → Settling → Idle`, `Error` на неуспешных сохранениях.
2. Реализовать `SpinService.StartSpin` с проверкой ставки, баланса, состояния и `SpinId`.
3. Для paid Spin **до генерации/анимации** сохранить уменьшенный баланс и `PendingSpin` одной операцией. Для Free Spin зарезервировать/уменьшить остаток.
4. Генерировать `SpinOutcome` и потенциальный jackpot, но не зачислять награды до окончания анимации.
5. Реализовать `CompleteSpin(SpinId)` с однократным settlement: выигрыш, retrigger, недельный jackpot и удаление pending сохраняются одним snapshot.
6. Реализовать запрет второго запуска/смены ставки/Back в не-Idle, в том числе в API, независимо от UI.
7. При загрузке состояния с `PendingSpin` удалять pending без повторного дебета, без jackpot/free spins win и без восстановления ставки.
8. Обработать ошибку записи settlement: не возвращаться в Idle, не объявлять награду выданной; допускать retry той же операции по SpinId.
9. Добавить тесты «закрыли после debit», «закрыли после settlement», «повторно вызвали Complete», «дебет не сохранился», «Free Spin прервали».

**Критерий завершения:** невосстановленное вращение всегда теряет **только уже списанный ресурс**, но не начисляет рассчитанный выигрыш; без двойного списания/начисления.

### 4.7. Application: Daily Bonus

1. Реализовать `IClock` и тестовые часы.
2. Реализовать `DailyBonusService` и семидневную последовательность наград из SO.
3. Учитывать UTC-сутки, получение только вручную, сброс серии после пропуска.
4. В одной транзакции сохранять дату получения, день серии и новый баланс.
5. Подготовить UI DTO с доступностью, размером текущей/следующей награды и временем обновления.

**Критерий завершения:** бонус нельзя получить дважды за сутки; корректно работает 7-дневный цикл, пропуск и UTC-полночь.

### 4.8. Application: Jackpot of the Week

1. Реализовать `WeeklyJackpotService` с `WeekId`, состоянием события, лимитом выигрыша.
2. Добавить суммы и вероятности в конфиг с базовым примером `100 000 монет / 0,01% при 1 000 bet`.
3. Для платных Spin вычислять шанс с учётом ставки, тестировать конкретные границы `0 / 1` и разные bet.
4. Проверить начисление **только на settlement** и фиксацию лимита в том же сохранении.
5. Реализовать восстановление доступности при переходе на следующую неделю.
6. Предоставить Presentation `JackpotViewModel` с amount, state, reset UTC.

**Критерий завершения:** максимум один оплаченный jackpot в неделю, бесплатные вращения не участвуют, прерванный Spin не потребляет лимит.

### 4.9. Presentation: главное меню, Settings, Daily bonus

1. Собрать `MainMenuScreen` с **тремя обязательными кнопками**: Play, Settings, Daily bonus.
2. Реализовать `MainMenuPresenter` и `GameNavigationService`/screen router.
3. Settings: музыка/звук, громкость, локальное сохранение пользовательских предпочтений.
4. Daily bonus: семидневные награды, Claim, состояние уже полученной награды, индикатор на кнопке главного меню.
5. UI вызывает Application-контракты, не трогает `SaveRepository`/баланс напрямую.

**Критерий завершения:** все три кнопки работают, награда начисляется единожды, экран переключается без scene reload.

### 4.10. Presentation: слот, барабаны и управление

1. Собрать `SlotScreen` с матрицей 5 × 3, балансом, ставкой, Spin, Back, last win, Free Spins remaining.
2. Создать `ReelView` с анимацией **пяти отдельных барабанов**, stagger остановок и результатом из `SpinOutcome`.
3. Добавить `PaylineView`, подсветку выигравших символов и Scatter-анимацию.
4. Добавить `SlotPresenter`, управляющий `interactable` по состоянию `GameSession`.
5. По сигналу о полном окончании Spin запускать `CompleteSpin(SpinId)` и только после подтверждённого сохранения показывать начисленный выигрыш.
6. `Back` и изменение ставки сделать недоступными на любой критической стадии, в том числе при сохранении/ошибках.
7. Остановку или ускорение анимации при желании реализовать без перегенерации результата. Убедиться, что отключение `SlotScreen` не завершает Spin автоматически.

**Критерий завершения:** все вращения визуально приводят к заранее рассчитанной матрице, возврат в меню невозможен во время активного Spin, никакие tween callback не начисляют баланс напрямую.

### 4.11. Presentation: постоянный JackpotHUD

1. Добавить JackpotHUD как неизменяемую часть верстки `SlotScreen` (не как временное popup).
2. Показать сумму, `Active/Won this week/Inactive`, время/дату недельного обновления.
3. Обновлять интерфейс из ViewModel, при необходимости по `IClock` раз в секунду без изменения Domain.
4. При выдаче выигрыша показать отдельную анимацию, **не скрывая HUD навсегда**.
5. Проверить состояние при Free Spins, в ходе вращения и после смены недели.

**Критерий завершения:** информация о jackpot постоянно видна на слоте и обновляется при изменении параметров/состояния.

### 4.12. EditMode-тесты, симуляция и балансировка

1. Объединить тесты реальных reel strips, win evaluator, scatter, jackpot и бонусной экономики.
2. Написать массовую детерминированную симуляцию **100 000–1 000 000+** платных Spin без анимаций, с учётом цепочек Free Spins.
3. В отчёте различать base-game RTP, бонусный RTP, payout Jackpot и суммарную отдачу; тестировать частоту Scatter и дисперсию.
4. Проверить расчётные значения из TZ, выбирать статистические допуски с учётом распределения выплат.
5. Добавить регрессионные fixed-seed тесты на конкретные последовательности, чтобы изменение лент или выплат было видно в CI.
6. Сделать не менее 5 рискованных сценариев по жизненному циклу и восстановлению: двойной Spin, quit during spin, quit after settlement, failed save, weekly/daily boundary.

**Критерий завершения:** тесты воспроизводимо проходят без открытия сцены, есть понятный отчёт о соответствии математике.

### 4.13. PlayMode, lifecycle и финальная проверка

1. Проверить запуск из чистого состояния, оба экрана и три кнопки меню.

**Критерий завершения:** полный пользовательский сценарий от меню до jackpot/free spins работает устойчиво; выход в меню/закрытие ведут себя в соответствии с TZ.

## 7. Критические риски и меры

| Риск | Мера |
|---|---|
| Баланс списан только в памяти и восстанавливается после закрытия | Сохранять debit + `PendingSpin` **до** старта анимации; тест kill/reload |
| Выигрыш сохраняется раньше завершения Spin, вопреки принятой политике | Чётко разделить accept/debit и completion/settlement; payout только после подтверждения окончания и успешного save |
| Пользователь обходит disabled `Back` и прерывает активную сессию | Проверять `GameSession` на уровне Application; UI только отражает запрет |
| Двойной клик или повторный callback начисляет выигрыш повторно | `SpinId`, атомарный settlement, запрет конкурирующих команд и идемпотентные проверки |
| Ошибка записи/повреждение сохранения теряет всю сессию | Snapshot + temp/backup, versioned schema, безопасное восстановление, fake-error tests |
| Переход UTC-полуночи в середине Spin ломает weekly jackpot | Фиксировать `WeekId` на приёме Spin и тестировать пограничный сценарий |
| Daily Bonus можно получить дважды в одном дне | Атомарно сохранять награду вместе с `LastClaimUtc` |
| Путается RTP выплат по линиям и экономика Daily Bonus | Отдельные статистики base line, Free Spins, jackpot; Daily Bonus не включать в RTP |
| Фиксированная seed остаётся в production | Тестовый RNG только при явно включённом debug флаге, по умолчанию false |
| Логика зависит от Tween/MonoBehaviour | Чистый SlotEngine; Presentation только показывает DTO |
| При Remote Config сломаются Sprite-ссылки и активные бонусы | `SlotRuntimeConfig` с `SymbolId`, локальный visual config и snapshot/version на время Spin и bonus chain |
| Сумма jackpot ошибочно воспринимается как общий фонд на всех игроков | Сразу документировать персональный локальный jackpot без серверной синхронизации |
| Рост объёма из-за UI/полировки | Завершать этапы с критериями; final art, онлайн-сервисы и дополнительные механики вынести за MVP |

## 8. Проверочные сценарии (минимальный ручной чек-лист)

1. **Новый игрок:** Main Menu, стартовый баланс 20 000, три кнопки, слот открывается через Play.
2. **Обычный Spin:** ставка списана после принятия, результат совпадает с показанной матрицей, начисление только после окончания.
3. **Попытка Back во время Spin:** кнопка выключена; программный `NavigateToMenu` отклонён; Spin не прерывается.
4. **Закрытие во время платного Spin:** после перезапуска ставка потеряна, никакой Line Win/Scatter/Jackpot не добавлен.
5. **Закрытие после settlement:** баланс и все заработанные Free Spins/Jackpot корректно сохранены.
6. **Free Spin с аварийным закрытием:** один Free Spin потрачен; выигрыша/retrigger нет; оставшаяся очередь сохранена.
7. **Daily Bonus:** Claim удваивать нельзя; получение на следующую дату работает; пропуск сбрасывает серию.
8. **Jackpot:** вероятность/сумма берутся из SO; при тестовом гарантированном выигрыше награда зачисляется один раз на неделю; в Free Spins событие не разыгрывается.
9. **JackpotHUD:** виден до, во время и после Spin, не пропадает после выигрыша; отображает состояние/сумму/сброс.
10. **Ошибки:** запись запрещена → Spin не стартует или settlement не объявляет успех; нет ложного начисления.
11. **Конфигурация:** изменение paytable/настроек jackpot из SO меняет результат после следующего bootstrap, не требует правок C# кода.
12. **Стресс-тест:** фиксированный seed воспроизводит измеренные показатели на 1 000 000+ Spin, не требует Canvas и не создаёт Unity объектов.

## 9. Definition of Done

Готово, когда выполнены все критерии `TZ.md` §14, пройдены ключевые `EditMode`/`PlayMode` тесты, продемонстрированы оба экрана из одной Unity-сцены, а критические гарантии проверены:

- Чистый C# Domain и отделённая Application-логика;
- Работа с конфигурацией через ScriptableObject → `ISlotConfigProvider` → `SlotRuntimeConfig`;
- Корректные 20 paylines, Scatter, Free Spins и баланс;
- Daily Bonus и персональный Jackpot of the Week, постоянный HUD на слоте;
- Во время Spin нельзя вернуться в Main Menu;
- Внезапное закрытие до settlement теряет ставку/Free Spin, но не начисляет возможный выигрыш;
- Повторные команды не вызывают двойных действий;
- Сохранения и загрузка устойчивы к прерванному Spin и типовым ошибкам;
- Тесты и математический simulation report доступны в репозитории;
- README описывает архитектуру, ограничения и запуск из чистого checkout.
